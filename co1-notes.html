COI-1 Python Basics and Decisions

Lecture 1 covers the raw material of every program that follows: variables, the four core data types, conversion, operators, and decision rules. Every later module (pandas, SQL, automation) is built out of these pieces.

1.1 Variables — names that point to values

A variable is a name that points to a value stored in the computer’s memory — like a sticky-note label on a box that holds something: unit_price → 45.50. You create one by assignment:

product_name = "Notebook"      # text
unit_price = 45.50             # decimal number
quantity = 12                  # whole number
  • Dynamic typing: Python decides the type from the value — you never declare types.
  • Re-assignment: a label can point to a new value at any time. Catch: total_cost computed from an old quantity is not updated when quantity changes — Python does not track formulas, only stored values.
  • Multiple assignment & swap: shop_a, shop_b = 5, 10 creates two variables in one line; shop_a, shop_b = shop_b, shop_a swaps them with no temp variable.
  • Read = as “gets”, not “equals”: the right side is worked out first, then stored under the name on the left.

Naming rules (enforced by Python): letters, digits and _ only · never starts with a digit · no spaces or - $ @ · case-sensitive (price and Price are different names) · never a keyword (class, if, for …).

DO

  • snake_case: total_price, gst_amount
  • meaningful names — a reader should know what it holds
  • short but readable; plural for collections (products)

DON’T

  • 1st_item — starts with a digit (SyntaxError)
  • my price — space in the name (SyntaxError)
  • x, a1 — meaningless for business data
  • print, list, sum as names — hides Python’s built-ins
# Case sensitivity — two separate variables:
price = 100
Price = 999
print(price, Price)              # 100 999
ErrorWhen you see it
SyntaxErrorillegal name (class = 5), = used where == was meant in a condition, missing colon
NameErrorusing a name that was never created — usually a typo or a wrong capital letter (prce)

MONEY NOTE

Don’t store exact accounting in float — tiny rounding errors appear (Section 1.4 shows why and the house rule for it). A proper money tool arrives in later modules; for CO1 the rule is round(x, 2) before you display or compare.

1.3 Conversion (casting) & input

Convert one type to another with int(x), float(x), str(x), bool(x). The rule that saves your day: data from forms, files and input() arrives as text — convert it before you do any maths.

qty = int(input("Quantity: "))        # text "3"  -> number 3
rate = float(input("Rate: "))         # text "25.5" -> 25.5
total = qty * rate
print(f"Total bill: {total}")
ConversionWatch out
int("abc")ValueError — not a number at all
int("3.5")also a ValueError — two steps: int(float("3.5"))
int(7.9)cuts to 7 (truncation), it does not round. round(7.9) gives 8.
"100" + 5TypeError — text plus number. Fix: "100" + str(5) or int("100") + 5

Truthy / falsy: bool(x) is False for exactly 0, "" (empty text), None — almost everything else is True. Sneaky case: "0" is text, so it is True.

print(bool(0), bool(""), bool(None))      # False False False
print(bool(5), bool("hello"), bool("0"))  # True  True  True  ← "0" is text, not zero

THE TWO BIG ONES

= stores a value; == asks whether two values are equal. / always gives a float (10/2 → 5.0); // gives the whole number (5). Use round(x, 2) to display money.

THE FLOATING-POINT SURPRISE

0.1 + 0.2 is 0.30000000000000004 — so 0.1 + 0.2 == 0.3 is False. Money in India has exactly two decimal places (paise): accumulate normally, round(x, 2) only at the end, and never compare money with ==.

running = 0
for amount in [19.99, 19.99, 19.99, 19.99, 19.99]:
    running += amount
print(running)                # 99.94999999999999
print(round(running, 2))      # 99.95   ← clean
print(running == 99.95)       # False — never do this with money

1.5 Conditionals — if / elif / else

The program checks conditions top to bottom; the first True branch runs, all the rest are skipped. Two anatomy rules: the condition line ends with a colon :, and the block is indented 4 spaces.

marks = 72
if marks >= 90:
    grade = "A+"
elif marks >= 75:
    grade = "A"
elif marks >= 60:
    grade = "B"
else:
    grade = "C"
print("Grade:", grade)     # B

Tiers + an independent bonus — the tiered-discount pattern:

order_total, is_member = 7500, True
if order_total >= 10000:  discount_rate = 15
elif order_total >= 5000: discount_rate = 10
elif order_total >= 1000: discount_rate = 5
else:                     discount_rate = 0

if is_member:             # separate if — it is an independent rule
    discount_rate += 2
# 7500 -> 10% + 2% member = 12% off
  • Put the most specific condition first. A broad if marks >= 40: print("Pass") placed before a marks >= 75 check catches everything and the distinction branch is never reached.
  • Truthiness in conditions: write if is_paid: — never if is_paid == True. An empty list is False: if not cart: means “cart is empty”.
  • Membership test: if city in ("Pune", "Mumbai", "Nashik"): — one test for a list of options instead of three ors.
  • Peak-rate pricing is just this pattern: choose a price by hour with if / elif / else; the first True branch wins.
ErrorCause
SyntaxErrormissing colon (if marks > 50), or = written where == was meant (if marks = 50:)
IndentationErrorthe line under if is not indented; mixing tabs and spaces also breaks it

COI-2 Data Structures and Loops

Lecture 2 scales you from “one value” to “many values”: lists, dictionaries, the real-business pattern of a list of dictionaries, tuples and sets — and the two loops that process them.

2.1 Lists — ordered and changeable

A list keeps many items in one variable, in order, inside [ ]. Indexing starts at 0; -1 is the last item, -2 the second-to-last.

products = ["Pen", "Notebook", "Bag", "Lamp"]
print(products[0])     # Pen   ← first
print(products[-1])    # Lamp  ← last
print(len(products))   # 4

Slicing x[start:stop] — the stop is NOT included:

print(products[1:3])   # ['Notebook', 'Bag']   ← indices 1 and 2
print(products[:2])    # from the start
print(products[2:])    # to the end

Lists are mutable: order[1] = 5 changes the item in place, and the membership test "Bag" in products tells you whether a value is present.

The examiner’s contrast: a bare index past the end raises IndexError (products[4] on a 4-item list); a slice past the end does not — it is silently clipped (products[1:9] just returns what exists). One raises, one never does.

2.2 Dictionaries — key → value records

A dictionary stores key : value pairs inside { }. You look things up by key, not by position — ideal for one product, customer or invoice.

customer = {"name": "Ravi Kumar", "city": "Chennai", "orders": 3}
print(customer["name"])                    # Ravi Kumar

customer["phone"] = "90000-00000"         # new key -> added
customer["orders"] = 4                   # old key -> value replaced

print(customer.get("email", "not provided"))  # default instead of an error
print("city" in customer)                # True — checks KEYS
ToolWhat it gives
d[k]value for key k — KeyError if k is missing
d.get(k, default)value for k, or the default — the safe lookup; use it when a key may be missing
d.keys() / d.values() / d.items()all keys / all values / all (key, value) pairs
d.update(other)add or change many pairs at once
d.pop(k)remove key k and give its value back
del d[k]remove key k, value discarded
  • Keys must be unique and unchangeable (text, numbers, tuples — never a list). A repeated key is not an error: the last value silently wins ({"a": 1, "a": 2} → {'a': 2}).
  • KeyError — d["Rocket"] when the key does not exist; TypeError (“unhashable”) — trying to use a list as a key.
  • A price list is the running example: price_list = {"Rice": 62, "Dal": 140, ...} — read, change a price, add a product, and price a whole cart by looking each item up by its key.

2.3 Lists of dictionaries — the real business pattern

A spreadsheet is a list of rows; each row is a dictionary of column → value. This is the structure you will meet in every later module (it is exactly what a pandas DataFrame becomes):

orders = [
    {"customer": "Ravi", "item": "Notebook", "qty": 10, "price": 45},
    {"customer": "Sita", "item": "Pen",      "qty": 25, "price": 10},
    {"customer": "Anil", "item": "Bag",      "qty": 2,  "price": 499},
]

print(orders[1]["customer"])                 # Sita — list index FIRST, then dict key
print(orders[-1]["price"] * orders[-1]["qty"])  # 998

orders[0]["qty"] = 12                       # update a record
orders.append({"customer": "Meena", "item": "Lamp", "qty": 1, "price": 650})

DO

  • One dictionary per record, same keys in every record
  • Read in two steps: orders[0]["item"]
  • Keep key spelling consistent (qty everywhere)

DON’T

  • Keep parallel lists (names, prices) that can drift apart
  • Spell a key two ways (qty vs quantity) — orders[0]["quantity"] is a KeyError
  • Try orders["customer"] — a list takes an integer, not a key (TypeError)

The accumulator pattern on records: start total_value = 0 before the loop, add product["qty"] * product["price"] inside it — one running total for the whole stock.

# tuple: fixed, and it UNPACKS
dimensions = (30, 20, 10)

# dimensions[0] = 50  →  TypeError: tuples do not support item assignment

# set: duplicates disappear automatically
cities = ["Pune", "Delhi", "Pune", "Mumbai", "Delhi"]

# set arithmetic — who is in both / either / only A?
shop_a = {"Pen", "Book", "Bag"}
shop_b = {"Book", "Lamp"}
print(sorted(shop_a & shop_b))          # in BOTH: ['Book']
print(sorted(shop_a | shop_b))          # in EITHER
print(sorted(shop_a - shop_b))          # only in A: ['Bag', 'Pen']

Sets have no order, so you cannot index them (s[0] → TypeError “set is not subscriptable”); wrap in sorted() when you need a tidy list. visits.count("Ravi") on the raw list answers “how many times did they come”; set(visits) answers “how many different customers”.

2.5 Picking a structure

When a new piece of data appears, ask one question: how will I use it?

  • I will go through it one by one, in order, and it grows or changes → list — daily sales, a shopping cart, a queue of orders.
  • I will look a value up by a name or code → dict — price by product, orders by customer.
  • The values must not change once recorded → tuple — a shop’s lat/long, an (id, code) pair you do not own.
  • Only which items, not how many matters → set — the cities customers live in, repeat visitors.

And when the data is many records of the same shape — orders, invoices, customers — it is a list of dictionaries: the pattern that becomes a spreadsheet, and later a DataFrame in CO2.

COI-3 Functions and Automation

Lecture 3 turns one-offs into tools: reusable functions, habits that make code readable, reading the errors you will actually meet, and the automation project that ties it all together.

3.1 for loops — repeat for each item

A for loop repeats the same steps for every item in a collection. Name the loop variable as one item: for product in products.

products = ["Pen", "Notebook", "Bag"]
for product in products:
    print("Packing:", product)
  • range(start, stop, step) counts — the stop number is NOT included: range(1, 4) gives 1, 2, 3; list(range(0, 10, 2)) gives [0, 2, 4, 6, 8].
  • Accumulator pattern — the single most important loop shape in this course: 
    total = 0                       # start BEFORE the loop
for amount in sales:
    total += amount             # add each amount to the running total
    Never reset total = 0 inside the loop.
  • Loop a dictionary with for item, price in prices.items(): — one line gives you both sides of each pair.
  • Best-day pattern (loop + if): start best = weekly_sales[0], then update best whenever a bigger amount shows up.
  • Counter pattern: start count = 0, and count += 1 inside an if — how many days exceeded 10,000.

Errors you will meet: TypeError — for x in 5 (a number is not iterable; you probably meant range(5)); NameError — using the accumulator before creating it.

3.2 while loops, break & continue

while repeats as long as a condition stays True — use it when you do not know in advance how many rounds you need (“until done”). Something inside the loop must change the condition, or it never stops.

stock = 5
while stock > 0:
    print("Selling... stock left:", stock)
    stock -= 1                    # without this line → infinite loop!
print("Sold out")
  • break — leave the loop immediately. Example: scan prices, if price > 1000: print(...); break — no need to look further.
  • continue — skip the rest of this round, go to the next item. Example: if price < 100: continue skips cheap items.
  • Repayment schedule pattern: while balance > 0: take a fixed monthly payment, floor the balance at 0 so a final partial payment never shows a negative.
  • Choosing: known collection → for; condition → while.
  • The repeat-until-valid pattern: while True: read the input, if it is valid: break. It is the only safe shape of while True — the break must be reachable whenever the input is correct.
  • Stuck in an infinite loop? Press the Stop (■) button in your IDE/notebook, or Ctrl + C in a terminal. Never use while True: without a break you can actually reach.

3.3 Functions — write once, use many times

A function is a named block of code: it takes inputs (parameters) and can hand back a result.

def calculate_gst(amount, rate=18):
    """Return the GST for an amount (default rate is 18%)."""
    return amount * rate / 100

print(calculate_gst(2500))        # 450.0 ← default rate used
print(calculate_gst(2500, 5))     # 125.0 ← rate given
  • Definition: def name(params): + docstring + body + return. Define once with def, call as many times as you like.
  • Default parameters (rate=18) make arguments optional; positional arguments come in order.
  • Functions call functions: invoice_total can call calculate_gst inside it — compose small jobs into bigger ones.
  • A function that only does something (print) is fine; one that should give a value back must return it.
  • Keyword calls: calculate_gst(amount=2500, rate=5) names each argument — order no longer matters and the call explains itself. The usual exam shape is one required argument plus one defaulted: def f(x, y=10):.
PRINT VS RETURN — THE CLASSIC TRAP
def gst_print(amount):
    print(amount * 0.18)          # shows a value, gives nothing back

def gst_return(amount):
    return amount * 0.18          # gives the value back - reusable!

result_a = gst_print(1000)        # prints 180.0 ...
result_b = gst_return(1000)
print(result_a, result_b)         # None 180.0
print(result_b + 100)            # ... only the returned one you can keep using

A function without return gives back None. If you only printed inside, you cannot calculate with the result.

Scope: variables created inside a function stay inside. bill in make_bill() is not visible outside — print(bill) after the call is a NameError. That is the point: the function’s inside is private.

Errors: TypeError — you forgot a required argument (price_with_gst() with no price); NameError — reaching for an inner variable outside.

3.5 Reading a traceback

When code breaks, Python prints a traceback. Read it from the bottom up:

  1. Last line = the error name + cause. KeyError: 'Rocket' says the missing key; TypeError: can't concat str to int says you mixed text and number.
  2. File ..., line N = where. The last file/line pair is the exact line that broke.
  3. The offending expression is shown just above the error line.
ErrorMeaningUsual fix
KeyErrora dictionary key that is not therecheck the spelling; use .get() for safe lookups
TypeErrorwrong kind of value for the operationconvert types (int("100")); don’ mix text and numbers with +
ZeroDivisionErrordividing by zeroguard with if denominator > 0
IndentationErrorthe block under if/for/def is not indented (or mixed tabs/spaces)4 spaces, consistent

This is also exactly the text you will hand to an AI coding assistant (3.6) — a traceback is a first-class tool, not an obstacle.

3.6 AI coding assistants (Copilot · Claude · Codex)

A good prompt is: context + the exact error + what you tried.

  • Paste the full traceback (not “it&rs;s broken”), plus a tiny snippet that reproduces it.
  • Say what the code is supposed to do; ask it to explain the error first, then fix it. Example prompt: “inventory = {'Pen': 10}. I want a safe lookup that gives 0 if the key is missing. Show the one line of code.” → inventory.get("Rocket", 0).
  • For refactors: “Refactor this into one well-named function with named constants and a docstring; keep the output identical.” Then run it and compare — the assistant drafts, you check the work.
  • Review every line it writes — you stay responsible for the result.
  • Never paste private data into a public tool.

3.7 The automation project — a daily sales report

Do the task by hand once, then let Python repeat it every day. Four steps:

StepWhat you do
1 · Collectstore the day’s orders in a list of dictionaries (item, qty, price)
2 · Calculateloop through the orders and add up the line totals (accumulator)
3 · Reuseput the line maths in one function with a return
4 · Reportprint each line and the daily total
orders = [
    {"item": "Pen",  "qty": 10, "price": 5},
    {"item": "Book", "qty": 2,  "price": 60},
    {"item": "Bag",  "qty": 1,  "price": 450},
]

def line_total(order):
    """Return the line amount for one order record."""
    return order["qty"] * order["price"]

total = 0
for order in orders:
    amount = line_total(order)
    total += amount
    print(f"{order['item']}: {amount}")
print(f"Daily total: {total}")
# Pen: 50 / Book: 120 / Bag: 450 / Daily total: 620

The payoff of the design: add a fourth order and re-run — the report updates with no other change. The CO1 homework extends it: add 18% GST per line and print the grand total (see the checklist at the end) — that extension is a natural apply-level exam question.

3.8 Building confidence from zero — four habits

1 · TYPE IT YOURSELF

Typing builds memory that copy-and-paste never will. Retype every worked example on this page.

2 · PREDICT, THEN RUN

Guess the output first, then check yourself. Output-trace questions are this habit, formalised — and it is also the skill that lets you verify an AI assistant’s answer instead of trusting it.

3 · READ THE ERROR

The traceback names the line and the problem. Bottom-up: error name, then where, then the expression. Section 3.5 is the map.

4 · START SMALL

Get a tiny version working, then grow it — one item before many, one function before the report, the pass stub before the real body.

QUICK CHECK — PREDICT, THEN OPEN
marks = 65; grades: A — ≥ 75, B — ≥ 60, else C. Which grade?
ANSWER

B — 65 fails the A check and passes the B check; the loop of conditions stops there.

A loop adds 5, 10 and 15 to a total that starts at 0. Final total?
ANSWER

30 — the accumulator pattern.

Which numbers does range(2, 10, 3) produce?
ANSWER

2, 5, 8 — stop (10) is not included.

What does a function without return give back?
ANSWER

None — it can still do its printing job, but you cannot use a value you never returned.

Attempt each question without looking; fold the answer open only after you have written yours. 2-mark = one sentence or one line plus its output. 5-mark = working code + expected output + one line explaining the pattern.

Section A · 2-mark questions

Q1. What is dynamic typing in Python? Give one advantage and one risk.
MODEL ANSWER

Python decides a variable’s type from its value at run time — no type declaration is written. Advantage: less boilerplate, faster prototyping. Risk: type mistakes surface only at run time ("100" + 5 is a TypeError), not before the program runs.

Q2. Which of these names are legal — 1st_item, total_price, my price, class, is_paid? Give the reason for each illegal one.
MODEL ANSWER

total_price and is_paid are legal. 1st_item starts with a digit (SyntaxError); my price contains a space (SyntaxError); class is a Python keyword (SyntaxError).

Q3. int(7.9) gives 7 but round(7.9) gives 8. Explain in one line.
MODEL ANSWER

int() truncates — it cuts the decimal part; round() rounds to the nearest integer.

Q4. Why is 0.1 + 0.2 == 0.3 False? How should money be compared instead?
MODEL ANSWER

Binary floating point cannot represent 0.1 or 0.2 exactly, so the sum is 0.30000000000000004. Compare money with round(x, 2) (or a small tolerance) — never with ==.

Q5. For stock = ["Pen", "Book", "Bag", "Lamp"]: what exception does stock[4] raise? What does stock[1:5] return, and why does it not raise?
MODEL ANSWER

stock[4] raises an IndexError — only indices 0–3 exist. stock[1:5] returns ['Book', 'Bag', 'Lamp']: a slice is clipped to the end of the list; it never raises.

Q6. A dictionary is written {"a": 1, "a": 2}. What is its value, and what is the rule?
MODEL ANSWER

{'a': 2} — keys must be unique; when a key repeats, the last value silently wins (no error is raised).

Section B · 5-mark questions

Q1. Write a program that takes an order total and a membership flag, applies a tiered discount (≥10000 → 15%, ≥5000 → 10%, ≥1000 → 5%, else 0%), gives members a further 2%, and prints the amount to pay rounded to 2 decimals. Show the output for total 7500, member True.
MODEL ANSWER
order_total = 7500
is_member = True

if order_total >= 10000:
    rate = 15
elif order_total >= 5000:
    rate = 10
elif order_total >= 1000:
    rate = 5
else:
    rate = 0
if is_member:
    rate += 2                       # independent rule - a separate if

amount_to_pay = round(order_total * (100 - rate) / 100, 2)
print(f"To pay: {amount_to_pay:,.2f}")    # To pay: 6,600.00

What is tested: the tiered if/elif ladder with the most specific tier first, and a separate if for the member bonus — an independent rule that adds to whatever slab was chosen, not an elif.

Q2. Write a function calculate_gst(amount, rate=18) that returns the GST, and a second function final_bill(total, is_member=False) that applies a 10% discount for totals ≥ 5000 (plus 2% for members), then adds GST on the discounted amount. Call both and show the outputs.
MODEL ANSWER
def calculate_gst(amount, rate=18):
    """Return the GST on an amount (default rate 18%)."""
    return amount * rate / 100

def final_bill(total, is_member=False):
    """Return the amount payable after discount and GST."""
    rate = 0
    if total >= 5000:
        rate = 10
    if is_member:
        rate += 2
    discounted = total * (100 - rate) / 100
    return round(discounted + calculate_gst(discounted), 2)

print(calculate_gst(2500))        # 450.0 ← default rate used
print(final_bill(7500, True))     # 12% off -> 6600.0, +1188.0 GST -> 7788.0

What is tested: def with a default parameter, return (not print), and one function calling another.

Q3. Predict the output of the snippet below and explain each line in one sentence.
SNIPPET
print(10 + 2 * 3 ** 2)
print(17 // 5, 17 % 5)
s = "KLU"
print(s * 2, len(s))
d = {"a": 1, "a": 2}
print(d)
MODEL ANSWER
  • 28 — power first (3**2 = 9), then multiplication (2 × 9 = 18), then addition.
  • 3 2 — whole-number division and remainder of 17 ÷ 5.
  • KLULKU 3 — * repeats a string; len() counts the characters of the original.
  • {'a': 2} — duplicate key; the last value silently wins.
Q4. Given a list of order dictionaries (keys item, qty, price), write code that prints each line total and the grand total, then also counts how many items are priced above 100. Name the two loop patterns you used.
MODEL ANSWER
orders = [
    {"item": "Pen",  "qty": 10, "price": 5},
    {"item": "Book", "qty": 2,  "price": 60},
    {"item": "Bag",  "qty": 1,  "price": 450},
]
total = 0
count = 0
for order in orders:
    amount = order["qty"] * order["price"]
    total += amount
    print(f'{order["item"]}: {amount}')
    if order["price"] > 100:
        count += 1
print(f"Grand total: {total}")      # 620  (50 + 120 + 450)
print("Priced above 100:", count)   # 1  (the Bag)

Patterns named: the accumulator (total, started before the loop, never reset inside it) and the counter (count, incremented inside an if).

Q5. Write a while loop that prints a repayment schedule: a loan of 50000 repaid at 12000 per month, the final partial payment floored at 0. Then explain (i) what happens if the update line is removed, and (ii) the difference between break and continue.
MODEL ANSWER
balance = 50000
month = 0
while balance > 0:
    month += 1
    balance -= 12000
    if balance < 0:
        balance = 0                  # floor - a final partial payment
    print(f"Month {month}: balance {balance}")
# Month 1: 38000 / Month 2: 26000 / Month 3: 14000 / Month 4: 2000 / Month 5: 0
  • (i) Without balance -= 12000 the condition stays True forever — an infinite loop. Something inside the loop must change the condition.
  • (ii) break leaves the loop immediately; continue skips only the rest of this round and moves on to the next item.
Q6. The snippet below works but is unreadable. Rewrite it as a named function with named constants and a docstring — the output must stay identical. Name the clean-code habits you applied.
BEFORE
x = [250, 1200, 80, 4500]
t = 0
for i in x:
  if i > 100:
    t = t + i * 0.18
print(round(t, 2))
MODEL ANSWER
GST_RATE = 0.18
MIN_TAXABLE = 100

def total_gst(invoice_amounts):
    """Return the total GST on invoices above the taxable minimum."""
    gst = 0
    for amount in invoice_amounts:
        if amount > MIN_TAXABLE:
            gst += amount * GST_RATE
    return gst

print(round(total_gst([250, 1200, 80, 4500]), 2))   # 1071.0 - unchanged

Habits applied: meaningful names (x → invoice_amounts, t → gst), named constants replacing the magic numbers 0.18 and 100, a one-job function with a docstring, and consistent 4-space indentation — output identical.
